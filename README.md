# pohudai

Telegram-бот для простого ведения питания, активности и веса без мини-аппа.

## Что уже есть в MVP

- онбординг: пол, возраст, рост, вес, активность, цель и желаемый вес;
- расчёт поддержания, дневной цели и ориентировочного белка;
- добавление еды обычным текстом или фотографией;
- уточнение распознанного блюда, запрос веса порции и подтверждение перед сохранением;
- КБЖУ для записи и быстрый остаток калорий за день;
- свободные команды вроде `запиши вес 81.2`, `сегодня прошел 9000`, `сколько осталось калорий`, `что сегодня ел`;
- запись веса и история взвешиваний;
- шаги + тип/длительность тренировки;
- календарь дней и страница конкретного дня;
- расчётный дневной расход и расчётный дефицит (не просто `цель - еда`);
- профиль и статистика за 7/30 дней;
- генерация 3 рецептов под остаток калорий/белка и добавление приготовленного блюда в рацион;
- вечерний опрос и итог дня, которые можно отключить;
- SQLite из коробки, PostgreSQL через `DATABASE_URL`.

AI используется как оценщик, поэтому калории и КБЖУ для фото остаются приблизительными. Перед сохранением еда подтверждается пользователем. Для брендовых продуктов модель не должна изображать поиск по официальной базе, если данных упаковки/этикетки нет.

## Запуск

Нужны Python 3.12+, токен Telegram-бота и OpenAI API key.

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
# заполнить BOT_TOKEN и OPENAI_API_KEY
python -m app.main
```

Docker:

```bash
docker build -t pohudai .
docker run --env-file .env pohudai
```

SQLite:

```env
DATABASE_URL=sqlite+aiosqlite:///./pohudai.db
```

PostgreSQL:

```env
DATABASE_URL=postgresql+asyncpg://user:password@host:5432/pohudai
```

## Архитектура

- `app/bot.py` — Telegram UX и FSM-сценарии;
- `app/ai_service.py` — распознавание еды и рецепты через OpenAI Responses API;
- `app/models.py` — пользователи, еда, вес, активность;
- `app/repository.py` — запись и агрегирование дневника;
- `app/calculations.py` — норма и оценочный расход;
- `app/scheduler.py` — вечерние сообщения;
- `app/main.py` — запуск.

## Следующие логичные шаги

1. Alembic-миграции и PostgreSQL по умолчанию для продакшна.
2. Redis для FSM при нескольких инстансах.
3. Open Food Facts / своя база продуктов для точных брендовых позиций.
4. Любимые блюда и «повторить вчерашний завтрак».
5. Фото холодильника, голос, штрихкоды и меню ресторана.
6. Персонализация расхода по нескольким неделям фактических шагов и динамике веса.
7. Интеграционные тесты Telegram- и AI-сценариев.
